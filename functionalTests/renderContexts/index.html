  • RenderContext Vector Drawing & Text Formatting

    This is a simple example showing the vector drawing methods of the render context. Vector drawing includes lines, points, line and curve paths, and primitive shapes and polygons. This demonstrates using the engine to render a static layout to a CanvasRenderer. You can also see the built-in vector-based font included with the engine.

    Inline formatting is supported by the TextParser, and the VectorTextParser extends that to the vector-based font. The "tags" are similar to those found in RTF documents to handle text formatting from within each string. In one example provided, you can see this:

    await api.vecText("{20}_{#00f}C{#f00}o{#080}l{#ee0}o{#808}r{#088}f{#800}u{orange}l_{!f}");

    That string produces the text "Colorful" at font-size 20, in rainbow colors, and italicized.

  • RenderContext Raster drawing

    Raster operations of the RenderContext covers objects like Sprites, Tiles, and TileMaps that are common in pixel-based games.

    Renderer-native font rendering with inline formatting is supported by the RasterTextParser.

  • The API, Intermediate Language & Renderers

    Your game will program against the high-level API of the RenderContext to generate visual output. The RenderContext abstracts away the complexities of generating output to a surface type (canvas, webgl, etc.) by producing an Intermediate Language (IL). The IL is consumed by the renderers to generate the actual rendered output.

    The IL has a syntax that is similar to Assembly Language, comprised of an operator like LINE, POINT, COLOR, and SHAPE followed by zero or more operands. The renderers interpret these commands to produce output from the context's API. Addressing Canvas2D or WebGl directly can be eliminated entirely.
