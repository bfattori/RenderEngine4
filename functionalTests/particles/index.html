Particle System

  • Single Effect and Particle Type

    Demonstrates the particle engine, running on the main thread, bound to the engine's update/render loop. Keeping particle limits low and effect sizes limited reduces overhead to an acceptable performance level. Limited to 500 particles per burst and a maximum 10,000 active particles.

  • An example using WebWorkers

    The particle engine can utilize WebWorkers if the browser supports them. The particle engine is distributed to worker threads, each sharing the burden, utilizing an Orchestrator to manage the distribution load and the coalescing and rendering of particles for the main thread.

    Running with WebWorkers can free up load in the engine's update/render loop for more active objects in the scene. This example uses 2 worker threads, increases the particles to 10,000 per burst, and has a maximum of 100,000 live particles.

  • Included particle types & effects

    The particle engine is flexible with base types for particles and effects, but extensible with a simple inehritance scheme. Particle types reduce the amount of state data needed, per particle, keeping the update/render operation fast.

    Particle effects generate particles and influence their spawning behavior to give the ultimate flexibility in the design and generation of repeatable particle effects.

    Included particle types:

    • BasicParticle - position, velocity, drag, dragRate, and gravity
    • AffectedParticle - Like basic, but affected by repulsors and colliders (increased CPU load)

    Included particle effects:

    • Spark - Configurable color palette, streak length, renders as lines, spawns sub-particle points, narrow spread-angle emission
    • Burst - Configurable color palette, particle sizes, renders as points, 360° emission
    • Puff - Configurable color palette, particle sizes, renders as diffuse points, 360° emission
    • Explosion - Configurable color palette, particle sizes, origin smoke properties, gravity influenced, renders as points, 360° emission
    • Fountain - Configurable color palette, particle sizes, renders as points or sprites, spread-angle emission
    • Fireworks - Pre-defined color palettes, renders as points, particles spawn sub-particles, built-in types: Peony, chrysanthemum, comet, palm, brocade, willow, pistil, tourbillion, fish, and strobe.
    • Smoke - Configurable color palette, renders as diffuse points, rises slowly, narrow spread-angle emission. This is an AffectedParticle.

  • Affectors

    Particle affectors are used to modify the behavior of `PhysicalParticles`. Primary examples of affectors are *repulsors* and *colliders* that push away particles, or provide a collision surface for particles. You can mix particle types so that only some particles are affected to improve overall performance.

    Particle repulsors are diffuse areas of influence over live particles. Each repulsor adds impulse to the particles that are within its range of influence. Repulsors are circular in shape with an effective strength that is greater near the origin of the repulsor. Repulsors add impulse to the particles via simple alteration of values, or a complex function that can generate turbulence or other effects.

    Particle colliders are lines that include a normal indicating the collision surface. When particles encounter a collider their movement stops or reflects, based on the collider's properies. Colliders allow for particles to visually interact with the game environment. Additional processing imposes extra CPU overhead.

  • Occlusion

    The particle engine runs separate from the game engine. Its only purpose is to move and render particles, so it doesn't care about the game's objects or surfaces. You can use repulsors and colliders, sparingly, to create the effects of environment interaction, but particles just render across the entire viewport unless blocked.

    That's where occlusion comes in. When objects in the game update, they can utilize the ParticleOccluder component to automatically generate an occlusion shape. With RenderContexts supporting multi-planar rendering (for parallax support or depth-of-field), objects with a ParticleOccluder component will generate an occluder shape based on their rendering-plane: none for background, hinted for middle, and assumed on for front. You can configure this per-object to override the default behavior.

    Occluders are collected into an "occlusion mask" that is applied to the particles as they are rendered into the scene. Occluders can create the effect of depth for the particles generated.
