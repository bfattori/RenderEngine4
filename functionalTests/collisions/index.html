Collision Systems

  • Broadphase Collisions

    The Broadphase collision system breaks the GameWorld viewport into manageable segments, allowing for quick determination if two objects are close enough to collide. This is a simple example of broadphase collision detection using a simple algorithm.

    Included in the engine is the GridBroadphase model that segments the world into developer-defined cells. As GameObjects in the world move, they generate events that the model is listening for. Objects are put into cells that represent an approximation of their location. GameObjects that have the potential for collision are emitted from the broadphase system in a PotentialCollisionList that can be passed to the narrowband model for more precise collision detections.

  • Narrowband Collisions

    The Narrowband collision system uses CollisionShape objects from a PotentialCollisionList to determine if two objects colliding. When a collision occurs, an event is emitted containing the CollisionData. This collision information contains back-off vectors and other information to determine the amount of overlap.

    As the collision events are fired, it is up to the game to determine what happens with the collision information provided. This gives the game developer the flexibility to determinine how to respond.

  • Raycasting

    The Narrowband collision models provide for ray-casting to determine when fast moving objects would have collided with another object updated its position and never directly overlapped the other object. Ray-casting can be used to examine the direction of travel to determine if the object passed through another.

  • Axis-aligned Bounding Box (AABB) Model

    Axis-aligned Bounding Boxes (AABB) align themselves to the world axis and provide a bounding box that encompasses the entirety of the GameObjects BoundingBox. As the BoundingBox moves, scales, or is rotated, the AABB will scale to contain the entire bounding box.

  • Centroid-aligned Bounding Circle (CABC) Model

    Centroid-aligned Bounding Circles (CABC) are centered on the GameObject with a radius that encompasses the BoundingBox of the GameObject. Bounding circles don't change in size, unless the GameObject is scaled up or down. Rotating the object will not change the radius of the bounding circle.

  • Convex Hull Model

    A Convex Hull is the set of points that minimally contain the GameObject within. The hull allows for more precise collision detection over AABB and CABC because it follows the contour of the object directly. Bits that protrude from an object will only be found in collision when the hulls overlap.
