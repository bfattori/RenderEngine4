Engine Basics

  • Configs & Configuring the RenderEngine4

    The engine is extremely flexible and extensible. While it can be the solution you use, it is much more valuable when you extend the engine for your own needs. This example shows how to configure the engine for a basic game setup.

    Config and TransferrableConfig objects are the backbone to the engine's flexible configuration style. The TransferrableConfig is primarily used when serializing and deserializing an object is necessary for transmission to a Worker thread, or over network boundaries. Objects can be created in one place, dehydrated, then sent to another location where the object is rehydrated as an exact copy of the original.

  • The Game World

    Almost everything that happens in the game, happens in the GameWorld. This is where GameObject instances exist, a reference to the game world's camera, the world transformation stack, and is where frame generation is performed.

  • The Event Engine

    A simple pub/sub style event engine is provided to coordinate messaging within the game. The event engine is also a factory that provides a private context to each GameObject for internal coordination.

  • Memory Management

    The RenderEngine4 provides memory management for game objects and associated value types. Allocations are provided by the SparkHeap and accessible through Spark data views. The Spark data view extends the system's DataView to provide additional methods for reading and writing game-specific data types such as vectors, 32-bit hex color values, and bit fields.

    Built on top of SparkHeap the FastMemoryPool and SlowMemoryPool provide functionality that avoids garbage collection as much as possible. The FastMemoryPool is used by math operations when manipulating vectors or arrays of values. The FastMemoryPool is destructive, in that values written to it may be quickly allocated to another process that needs the memory shape. Thus, allocations from the FastMemoryPool are intended to be used quickly and discarded.

    The SlowMemoryPool, on the other hand, uses indexing and memory coalescing to provide a location where values can be stored more long-term. Data is provided as a pointer to the actual value and the pointers are indexed to prevent re-use until the memory is freed. The flexibility of the fast and slow pools gives the developer options for enhanced performance.
